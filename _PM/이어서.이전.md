## 5. 결정사항·맥락

- **URL 수집 방식**: 매주 사용자 수동 `config.yaml` 갱신 (Gmail IMAP 자동 추출 미사용 — maily.so는 stibee 도메인이 아니라 기존 `fetch_stibee_url` 로직 재사용 불가, 수동이 가장 단순)
- **출력 포맷**: 헤더 라벨 없이 `📌 제목` + `부제(og:description)` + `1. 2. 3. 요약` + `URL` (사용자 선택 옵션 2)
- **요약**: 본문 스크래핑 후 LLM 자동 3줄 요약. 본문 캡 4000자.
- **데이터 모델**: 신규 dataclass 만들지 않고 `StibeeNewsletter` 재사용 — formatter/HTML v2의 stibee 카드를 자동 활용. `source="빌더조쉬"`로 식별, `topic` 필드에 og:description 저장.
- **금요일 출력 순서**: 빌더조쉬 → 까탈로그 → 롱블랙 (사용자 결정)
- **LLM 폴백**: Claude(anthropic) → Groq(qwen3-32b) → Gemini(2.0-flash). `_summarize`가 자체 폴백 로직 내장 (`formatter._call_with_fallback` 재사용 안 함 — 캡슐화 단순성).
- **fetch 시그니처**: `fetch(url, config: dict, source_name="빌더조쉬")` — config 통째로 받아 LLM 키들 추출. main 호출부도 동일 패턴.
- **HTML v2 카드**: 변경 불필요. `_render_stibee_v2`가 `StibeeNewsletter`를 자동 처리 (배지="빌더조쉬", og:image 자동 스크래핑).
- **인사말 컨텍스트**: `_build_greeting_prompt`의 기존 stibee_items 루프가 자동 처리.
- **config.yaml gitignore**: API 키 보호 차원에서 의도된 동작. 강제 추가하지 않음.
