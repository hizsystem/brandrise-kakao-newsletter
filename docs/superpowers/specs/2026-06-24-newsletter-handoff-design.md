# 데일리 뉴스레터 업무 핸드오프 설계

작성일: 2026-06-24

## 목표

데일리 마케팅 뉴스레터 운영 업무를 새 담당자에게 넘긴다. 두 가지를 만족해야 한다.

1. **API를 회사 계정으로**: Claude(Anthropic)·Gemini API 키를 모두 회사 계정에서 발급한 키로 교체하고, 비용이 회사 계정으로 청구되게 한다.
2. **관리 시스템을 공유 가능한 링크로**: 지금은 운영자 로컬 PC에서만 도는 관리 패널(`admin.py`, `localhost:5001`)을 호스팅해, 새 담당자가 링크만 열어 운영할 수 있게 한다. 파이썬·로컬 환경·코드 지식 없이 동작.

운영 프로세스는 지금과 동일하게 유지한다 — 매일 사람이 링크를 열고 URL을 붙여넣고 "생성"을 눌러 결과를 카카오톡 오픈채팅에 복사한다.

## 현재 시스템 (전제)

- **생성 파이프라인** (`main.py --now`): requests/beautifulsoup 기반 경량 스크래핑(브라우저 자동화 없음) → Claude API로 인사말 생성(실패 시 Groq→Gemini 폴백) → Gemini로 이미지 생성 → HTML 출력 → `docs/`에 저장 후 GitHub에 push → GitHub Pages 갱신.
- **관리 패널** (`admin.py`): Flask 앱, `localhost:5001`. 요일별 수동 URL 붙여넣기, "저장+생성" 버튼으로 `main.py --now` 실행, 정부지원사업 공고 발행, 실행 로그 표시. 비밀번호 로그인 코드 이미 존재(단, 비번 미설정 시 인증 생략).
- **설정** (`config.yaml`): 모든 API 키·관리자 비밀번호·GitHub 정보 보관. `.gitignore`에 포함되어 git에 추적되지 않음(개인 키가 git 히스토리에 노출되지 않은 상태).
- **출력 사이트**: GitHub Pages(`*.github.io/brandrise-newsletter`)로 이미 공개 링크 + 아카이브 제공. 코드와 `docs/`가 같은 저장소에 있음.

핵심 통찰: 최종 결과물을 카카오톡 오픈채팅에 **사람이 직접 복사**하므로 매일 사람이 한 번 개입한다. 따라서 "링크 열고 → 생성 클릭 → 복사" 흐름이 자연스럽고, 항상 켜진 서버(크론)는 필요 없다.

## 설계

### 1. 관리 패널 호스팅 (핵심)

기존 `admin.py`를 그대로 **Render 무료 티어 Web Service**에 배포한다. UI를 새로 만들지 않고 재사용한다.

- 결과: `https://<이름>.onrender.com` 형태의 공유 링크 + 비밀번호 로그인.
- 무료 티어 특성: 15분 미사용 시 인스턴스가 잠들어 **첫 접속만 ~50초 콜드 스타트**, 이후 정상. 월 비용 0원.
- 매일 "붙여넣기 → 생성 → 복사"가 한 세션에 끝나므로 무료 티어로 충분.
- 향후 콜드 스타트가 거슬리면 Railway(월 ~7천원, 항상 켜짐)로 코드 변경 없이 이전 가능.

배포 시 **자동 배포(auto-deploy)는 끈다**. 서버가 뉴스레터 콘텐츠를 같은 저장소 main에 push하므로, 자동 배포가 켜져 있으면 매 생성마다 서버가 재배포되는 루프가 생긴다. 코드 변경 시에만 수동 배포한다.

### 2. 비밀키를 환경변수로 (호스팅 전제)

지금은 모든 키가 로컬 `config.yaml`에 있다. 호스팅을 위해 비밀 값을 코드 저장소 밖으로 옮긴다.

- **비밀 값** → Render 대시보드 환경변수에 등록. 저장소엔 절대 들어가지 않음:
  - `ANTHROPIC_API_KEY` (회사 키)
  - `GEMINI_API_KEY` (회사 키)
  - `ADMIN_PASSWORD`
  - `GH_TOKEN` (GitHub push용)
  - `FLASK_SECRET_KEY` (세션 서명)
- **비밀 아닌 설정**(수집 소스 URL·포맷·요일 구조 등) → `config.base.yaml`로 저장소에 커밋.
- 서버 시작 시 부트스트랩 단계가 `config.base.yaml` + 환경변수를 합쳐 작업 디렉터리에 `config.yaml`을 생성한다. 그 결과 기존 `load_config()`/`save_config()` 코드와 `main.py`는 변경 없이 그대로 동작한다.
- 로컬 개발은 기존처럼 손으로 만든 `config.yaml`을 그대로 쓴다(부트스트랩은 `config.yaml`이 없을 때만 생성).

상태 영속성: 새 담당자가 붙여넣는 주간 URL은 매일/매주 새로 입력하므로 재시작 후 사라져도 무방하다(붙여넣고 같은 세션에 바로 생성). 비밀 값은 환경변수에서 매 시작 시 다시 주입되므로 영구 디스크가 필요 없다.

### 3. API를 회사 계정으로

- 회사 Anthropic Console에서 **새 API 키 발급** → `ANTHROPIC_API_KEY` 환경변수에 등록.
- 회사 Gemini(Google AI Studio) 계정에서 **새 API 키 발급** → `GEMINI_API_KEY` 환경변수에 등록.
- 로컬 `config.yaml`에 있던 **개인 Anthropic·Gemini 키는 발급처에서 폐기(revoke)** — 노출 방지.
- Groq/OpenAI 키는 현재 텍스트 생성 폴백 체인에만 존재하며 회사 계정 이전 대상이 아니다. 폴백이 실제로 필요하지 않으면 환경변수에 넣지 않는다(Claude 키만 있으면 동작).

### 4. GitHub Pages 발행 (서버에서)

- 서버가 생성한 HTML을 GitHub에 push → Pages 자동 갱신(현재 구조 유지).
- 서버에서 인증된 remote를 사용: `https://x-access-token:${GH_TOKEN}@github.com/<owner>/<repo>.git`.
- `GH_TOKEN`은 해당 저장소 한정 **fine-grained PAT**, contents 읽기/쓰기 권한.
- `github_push.py`의 `git commit`에 쓸 git user.name/user.email을 서버에서 설정(미설정 시 commit 실패 방지).
- 기존 `archive_sync` 가드는 그대로 유지.

### 5. 보안 (공개 링크라 필수)

- **관리자 비밀번호 필수화**: 현재 `login_required`는 비밀번호 미설정 시 인증을 건너뛴다. 공개 호스팅에서 비번이 없으면 누구나 접근 가능하므로, 호스팅 환경에서 `ADMIN_PASSWORD`가 비어 있으면 앱이 뜨지 않게(또는 모든 요청 차단) 막는다.
- `app.secret_key`를 `FLASK_SECRET_KEY` 환경변수에서 읽는다(현재는 config.yaml에 자동 생성·저장 → 호스팅 환경에선 재시작마다 세션 무효화되므로 환경변수 고정).
- HTTPS는 Render가 자동 제공.

### 6. 인수인계 문서

새 담당자용 한 장짜리 운영 가이드(`docs/HANDOFF.md` 또는 별도):

- 매일 루틴: 링크 → 로그인 → 오늘 URL 붙여넣기 → "저장+생성" → 1~2분 후 생성 텍스트 복사 → 카카오톡 오픈채팅에 붙여넣기.
- 요일별로 어떤 URL을 어디서 가져오는지(롱블랙=매일, 풋풋레터·캐릿=화, 빌더조쉬=수·금, 까탈로그=금, 헤이팝=목 자동).
- 정부지원사업 공고 발행 방법.
- 막힐 때 연락처/대응.

## 새 담당자의 하루 (핸드오프 후)

1. 공유 링크 열고 비밀번호 로그인 (첫 접속 시 ~50초 대기)
2. 오늘 해당하는 URL 붙여넣기
3. "저장+생성" 클릭
4. 1~2분 후 생성된 텍스트를 로그 박스에서 복사
5. 카카오톡 오픈채팅에 붙여넣기 (아카이브는 GitHub Pages에 자동 반영)

## 비용

- Render 무료 티어: 0원.
- Claude·Gemini API 사용량: 회사 계정으로 청구.

## 범위 밖 (이번에 하지 않음)

- 카카오톡 자동 전송(현재도 수동, 유지).
- 완전 자동 크론 발송(사람이 매일 개입하므로 불필요).
- 관리 UI 재설계(기존 그대로 재사용).
- Groq/OpenAI 키의 회사 계정 이전(폴백 미사용 시 제거 가능).

## 미해결/구현 시 확인 항목

- Render 런타임에 저장소 `.git`이 유지되어 push가 되는지 확인. 안 되면 시작 시 작업 디렉터리에서 인증 remote로 clone/pull하도록 보강.
- 회사 Gemini 키 발급 경로(Google AI Studio vs Vertex) 확인 — 현재 코드는 `generativelanguage.googleapis.com`(AI Studio) 키 형식 사용.
